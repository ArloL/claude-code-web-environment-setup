# Reading Mozilla's source, bugs and documentation. Separate from firefox.txt,
# which is about downloading the browser: nothing here is installed or built,
# these are the hosts that answer questions about Firefox's code, its bugs and
# how its platform is documented.

# Searchfox, the indexed cross-reference of mozilla-central. There is no mirror
# and no API on another host: both the search endpoint
# (searchfox.org/mozilla-central/search?q=...) and the rendered source pages
# (searchfox.org/mozilla-central/source/<path>) are served from this one host.
# Source of truth: https://github.com/mozsearch/mozsearch, whose deployment
# serves searchfox.org.
searchfox.org

# Bugzilla@Mozilla. Bug reports, their comments and their patches live only
# here, and the machine-readable form is on the same host:
# bugzilla.mozilla.org/rest/bug/<id> and /rest/bug?quicksearch=... answer
# anonymously for public bugs. The web UI needs JavaScript, so the REST API is
# what a fetch can actually read.
# Source of truth: https://bmo.readthedocs.io/en/latest/api/ and
# https://github.com/mozilla-bteam/bmo
bugzilla.mozilla.org

# MDN. The reference for what the web platform actually does -- and, unlike
# the two above, the one host here that is not Mozilla-project-specific: an
# answer about a DOM API, an HTTP header or a CSS property is checked against
# developer.mozilla.org rather than recalled. The rendered docs and the JSON
# behind them (append /index.json to any docs URL) are both on this host.
# Source of truth: https://github.com/mdn/content, whose build is deployed to
# developer.mozilla.org.
developer.mozilla.org

# The Mozilla wiki. Release process, project and platform pages that exist
# nowhere else -- this repo already depends on one of them: firefox.txt cites
# https://wiki.mozilla.org/Release_Management/Product_details as the source of
# truth for the Firefox version API, and that page could not be opened from a
# session until now.
# Source of truth: the wiki itself; it is the primary document, not a mirror.
wiki.mozilla.org

# Not listed, and not an oversight: raw attachment downloads from BMO are
# redirected to a per-attachment host under bmoattachments.org, so no exact
# entry covers them and wildcards do not work here (see network/README.md).
# Fetch attachment bytes through the REST API instead --
# bugzilla.mozilla.org/rest/bug/<id>/attachment returns the data base64-encoded
# from the host above.
